# Security policy

## Supported versions

Security fixes are provided for the latest published `0.1.x` release. Upgrade to the newest available patch before reporting a problem that may already be fixed.

## Report a vulnerability

Use [GitHub private vulnerability reporting](https://github.com/aimlesx/slack-axi/security/advisories/new) for suspected vulnerabilities. Do not open a public issue, discussion, or pull request for a vulnerability.

Include the affected version, macOS and Node.js versions, the command or component involved, impact, reproduction steps, and any proposed mitigation. Remove Slack credentials, authorization headers, private message or file content, action payloads, and personally identifiable workspace data. A maintainer may request the minimum additional evidence needed to reproduce the issue through the private report.

Reports are reviewed on a best-effort basis; this project does not promise a response or remediation service level. Please allow maintainers to investigate and coordinate a fix before public disclosure. If an incident involves unauthorized access to or loss of Slack API data, maintainers will follow the notification obligations in the Slack API Terms.

Use [GitHub Issues](https://github.com/aimlesx/slack-axi/issues) for non-sensitive defects and support questions.
